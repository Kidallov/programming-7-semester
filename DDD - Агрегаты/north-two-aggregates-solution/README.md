# Два агрегата магазина «Север»

Лабораторная работа по тактическому DDD. Проект реализует заказ `Order` и складскую
позицию `StockItem`: строки, цену-снимок, одного продавца, подарки, остатки,
резервирование, освобождение и истечение резервов.

## Запуск

Нужны Python **3.11 или новее** и, для основного способа запуска, установленный `uv`.
Зависимостей у проекта нет: используются только стандартные модули Python.
Команды выполняются из каталога, где находится этот README и `pyproject.toml`.

```bash
uv run python -m unittest discover -s tests -v
uv run python -m north_marketplace
```

Без `uv`, если `python3 --version` показывает 3.11+:

```bash
python3 -m unittest discover -s tests -v
python3 -m north_marketplace
```

В Windows вместо `python3` можно использовать `py -3.11` (или установленную более
новую версию). Интерактивного ввода нет. Не запускайте отдельные файлы пакета как
скрипты: точка входа — `python -m north_marketplace` из корня проекта.

## Ожидаемый вывод

```text
Заказ: order-100
Состояние: PLACED
Сумма: 1290.00 RUB
Физический остаток: 8
Доступный остаток: 7
Резерв reservation-900 создан по OrderId(order-100).
```

Демонстрация использует фиксированный срок 20 мая 2026 года, 12:00 UTC, как часть
учебного набора данных. Она не читает системные часы и не вызывает истечение.
Наступление срока само не меняет объект: это делает явная команда
`expire_reservations(now)`. Поэтому вывод воспроизводим независимо от даты запуска.

## Основные решения

- Изменение агрегата доступно через корень. Наружу выдаются кортежи неизменяемых снимков.
- Объекты-значения сравниваются по типу и содержимому. `OrderId("1")` не равен `BuyerId("1")`.
- Количество положительно, остаток неотрицателен, деньги используют конечный неотрицательный `Decimal`.
- Строки имеют собственные ID; один SKU может присутствовать в разных строках.
- Валюта и продавец едины. Подарок стоит ноль, платная строка стоит больше нуля.
- Разместить можно только полный черновик с платной частью. Отмена доступна из DRAFT и PLACED, повторная отмена запрещена.
- Доступность вычисляется: физический остаток минус активные резервы. Списание сохраняет активные резервы.
- Срок и `now` содержат часовой пояс. Истечение учитывает равенство сроку и возвращает число переходов.
- Резервы сохраняются после освобождения и истечения; их ID нельзя использовать повторно.
- `application.py` передаёт только OrderId, без взаимных вызовов корней и дублирования их проверок.

Код использует явные конструкторы, закрытые поля, обычные методы и `Enum`.
БД, HTTP, ORM, репозитории, события, очереди, фреймворки, `dataclass`, `@property`
и `Protocol` не используются. Прямое обращение к закрытым полям и низкоуровневый
обход Python через `object.__setattr__` не являются поддерживаемым API.

## Уточнения учебных примеров

Использован контракт практикума: `cancel()` без причины, `OrderLineId` и изменение
количества через корень. В демонстрации одна платная книга: увеличение до двух
из примера исходного model.md противоречило бы требуемой сумме 1290.00 RUB.
`active_reserved_quantity()` и `available_quantity()` возвращают `StockBalance`,
включая допустимый ноль; числовое значение читается через `.value()`.
